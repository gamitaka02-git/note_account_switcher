# noteアカウントスイッチャー

アカウントごとに独立したGoogle Chromeでnoteを開き、各アカウントと記事のアクセス状況を一覧表示するmacOSアプリです（0.2.0）。アプリのアイコンには同梱の `icon.png` を使用しています。

## 使い方

1. `noteアカウントスイッチャー.app` を開きます。
2. サイドバーの「アカウントを追加」から識別名と色を登録します。
3. サイドバーのアカウント名を押し、専用Chromeでnoteへログインします。
4. 集計期間を選び「すべて更新」または各行の更新ボタンを押します。
5. メイン一覧のアカウントをクリックすると記事別のアクセス状況を表示します。

集計期間は直近7日・28日・365日・全期間です。起動時は全期間が選択されています。記事モーダルではタイトル検索と各指標・公開日での並べ替えができます。
アクセス情報は手動で更新します。初回起動時や期間切り替え時に自動取得は行いません。
未取得やデータがない指標は「—」、取得失敗はメッセージで表示し、前回値を保持します。
表示値はnote側の集計時点の値であり、リアルタイム値ではありません。

パスワードはアプリでは保存しません。ChromeのCookieなどは次のフォルダにアカウント別で保存されます。

`~/Library/Application Support/NoteAccountSwitcher/Profiles/`

取得した数値・記事タイトルは同じ保存領域の `analytics.json` に期間別に保存します。
認証トークンは専用Chrome内だけで扱い、アプリには保存しません。

## 取得方式と制限

専用Chromeをローカル接続用ポート付きで起動し、noteのログイン済みページ内から、現行ダッシュボードと同じGraphQLの読み取り項目を取得します。
外部向けの公式連携APIではないため、noteの仕様変更時には連携処理の更新が必要になる可能性があります。
ログイン切れの場合はChromeでログインし直してから再度更新してください。
旧版から専用Chromeを起動したままの場合、一度その専用Chromeを終了してから更新してください。
通常のChromeのプロファイルは読み取りません。専用Chromeの連携ポートはローカルマシンからのみ利用します。
記事は続きのページも取得し、最大10,000件に達して続きがある場合は不完全なデータを保存せずエラーにします。

## ビルド

macOS 14以降とSwiftが必要です。Apple Silicon（arm64）とIntel Mac（x86_64）の
両方で動作するUniversal Binaryを生成します。

```zsh
chmod +x build.sh
./build.sh
```

取得処理のテスト（Node.js 20以降）：

```zsh
node --test mac/tests/fetch-analytics.test.mjs
```

上記テストはプロジェクトルートから実行します。ログイン済み先頭アカウントを使う実機取得テストは `node mac/tests/live-probe.mjs` です。
Mac版のみダッシュボード対応済みで、Windows版は従来のアカウント切り替え機能です。

`.app` をZIP化・コピーする場合は、実行権限を保持できる方法を使用してください。
実行権限が失われた既存のアプリは、上記の手順で再ビルドできます。

スイッチャーのウィンドウを閉じると、スイッチャーから起動した専用Chromeも終了します。
通常のChromeを別に起動している場合、そのChromeは終了しません。

## 削除について

アカウントのメニューには2種類の削除があります。

- 「一覧からのみ削除」：Chromeデータを残します。
- 「ログイン情報も完全に削除」：該当する専用Chrome領域を削除します。

このアプリを削除しただけでは、保存済みのChromeデータは削除されません。
